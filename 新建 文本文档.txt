launch_cvd
  └──▶ 解析参数、布尔参数处理、gflags
  └──▶ 生成 assemble_cvd 参数

1. 参数预处理与布尔标志转换

OverrideBoolArg：

Launch_cvd启动CF一共有三个过程：
1）启动参数预处理。主要是通过gflags库，完成对传入参数到FLAGS_XXX的转换。
2）调用assemble_cvd，生成配置文件---cuttlefish_config.json
3）启动run_cvd ，完成对虚拟机的启动

函数入口：host/commands/start/main.cc
核心函数是：
int CvdInternalStartMain(int argc, char** argv) {
  ::android::base::InitLogging(argv, android::base::StderrLogger);
  std::vector<std::string> args(argv + 1, argv + argc);
  std::vector<std::string> assemble_args;
  std::string image_dir;
  std::vector<std::string> args_copy = args;
  auto parse_res = ConsumeFlags(
      {GflagsCompatFlag("system_image_dir", image_dir)}, args_copy);
  LOG(INFO) << "Using system_image_dir of: " << image_dir;
  if (!parse_res.ok()) {
    LOG(ERROR) << "Error extracting system_image_dir from args: "
               << parse_res.error().FormatForEnv();
    return -1;
  } else if (!image_dir.empty()) {
    assemble_args = {"--system_image_dir=" + image_dir};
  }
  std::vector<std::vector<std::string>> spargs = {assemble_args, {}};
  FlagForwarder forwarder({AssemblerPath(), RunnerPath()}, spargs);
  // Used to find bool flag and convert "flag"/"noflag" to "--flag=value"
  // This is the solution for vectorize bool flags in gFlags
  args = OverrideBoolArg(std::move(args), BoolFlags());
  for (int i = 1; i < argc; i++) {
    argv[i] = args[i - 1].data();  // args[] start from 0
  }
  gflags::ParseCommandLineNonHelpFlags(&argc, &argv, false);
  forwarder.UpdateFlagDefaults();
  gflags::HandleCommandLineHelpFlags();
  setenv("CF_CONSOLE_SEVERITY", FLAGS_verbosity.c_str(), /* replace */ false);
  setenv("CF_FILE_SEVERITY", FLAGS_file_verbosity.c_str(), /* replace */ false);
  auto use_metrics = FLAGS_report_anonymous_usage_stats;
  FLAGS_report_anonymous_usage_stats = ValidateMetricsConfirmation(use_metrics);
  if (FLAGS_track_host_tools_crc) {
    // TODO(b/159068082) Make decisions based on this value in assemble_cvd
    LOG(INFO) << "Host changed from last run: " << HostToolsUpdated();
  }
  auto instance_nums = InstanceNumsCalculator().FromGlobalGflags().Calculate();
  if (!instance_nums.ok()) {
    LOG(ERROR) << instance_nums.error().FormatForEnv();
    abort();
  }
  // TODO(schuffelen): Lift instance id assumptions in sandboxing
  if (CuttlefishConfig::ConfigExists()) {
    auto previous_config = CuttlefishConfig::Get();
    CHECK(previous_config);
    CHECK(!previous_config->Instances().empty());
    auto previous_instance = previous_config->Instances()[0];
    const auto& disks = previous_instance.virtual_disk_paths();
    auto overlay = previous_instance.PerInstancePath("overlay.img");
    auto used_overlay =
        std::find(disks.begin(), disks.end(), overlay) != disks.end();
    CHECK(used_overlay == FLAGS_use_overlay)
        << "Cannot transition between different values of --use_overlay "
        << "(Previous = " << used_overlay << ", current = " << FLAGS_use_overlay
        << "). To fix this, delete \"" << previous_config->root_dir()
        << "\" and any image files.";
  }
  CHECK(!instance_nums->empty()) << "Expected at least one instance";
  auto instance_num_str = std::to_string(*instance_nums->begin());
  setenv(kCuttlefishInstanceEnvVarName, instance_num_str.c_str(),
         /* overwrite */ 1);
#if defined(__BIONIC__)
  // These environment variables are needed in case when Bionic is used.
  // b/171754977
  setenv("ANDROID_DATA", DefaultHostArtifactsPath("").c_str(),
         /* overwrite */ 0);
  setenv("ANDROID_TZDATA_ROOT", DefaultHostArtifactsPath("").c_str(),
         /* overwrite */ 0);
  setenv("ANDROID_ROOT", DefaultHostArtifactsPath("").c_str(),
         /* overwrite */ 0);
#endif
  auto assembler_input = WriteFiles(AvailableFilesReport());
  std::string assembler_output;
  auto assemble_ret =
      InvokeAssembler(assembler_input, assembler_output,
                      forwarder.ArgvForSubprocess(AssemblerPath(), args));
  if (assemble_ret != 0) {
    LOG(ERROR) << "assemble_cvd returned " << assemble_ret;
    return assemble_ret;
  } else {
    LOG(DEBUG) << "assemble_cvd exited successfully.";
  }
  std::string conf_path;
  for (const auto& line : android::base::Tokenize(assembler_output, "\n")) {
    if (android::base::EndsWith(line, "cuttlefish_config.json")) {
      conf_path = line;
    }
  }
  CHECK(!conf_path.empty()) << "could not find config";
  auto config = CuttlefishConfig::GetFromFile(conf_path);
  CHECK(config) << "Could not load config object";
  setenv(kCuttlefishConfigEnvVarName, conf_path.c_str(), /* overwrite */ true);
  std::vector<Subprocess> runners;
  for (const auto& instance : config->Instances()) {
    SharedFD runner_stdin = SharedFD::Open("/dev/null", O_RDONLY);
    CHECK(runner_stdin->IsOpen()) << runner_stdin->StrError();
    setenv(kCuttlefishInstanceEnvVarName, instance.id().c_str(),
           /* overwrite */ 1);
    auto run_proc = StartRunner(std::move(runner_stdin), instance,
                                forwarder.ArgvForSubprocess(RunnerPath()));
    runners.push_back(std::move(run_proc));
  }
  bool run_cvd_failure = false;
  for (auto& run_proc : runners) {
    auto run_ret = run_proc.Wait();
    if (run_ret != 0) {
      run_cvd_failure = true;
      LOG(ERROR) << "run_cvd returned " << run_ret;
    } else {
      LOG(DEBUG) << "run_cvd exited successfully.";
    }
  }
  return run_cvd_failure ? -1 : 0;
}

fruit::Injector<> injector(FlagsComponent);
然后：
injector.getMultibindings<LateInjected>() ➜ LateInject

• FlagFeature 是参数声明 + 验证 +默认值的模块。
• ProcessFlags(flag_features, args) 实际上就是用自定义的解析逻辑来替代 gflags::ParseCommandLineFlags。
• 这样可以用统一接口处理 flag，同时获得更强的类型安全、组合性（通过依赖注入自动注册 flags）。

下面详细分析使用 Fruit 依赖注入（DI）机制来解析和处理 flags 的例子
背景：Cuttlefish 用 Fruit 来声明和处理参数
传统 gflags 写法长这样：（以proxy_fastboot为例）
DEFINE_string(proxy_fastboot, "", "");然后通过xxxxx函数将传入参数解析到xxx。

但在 Cuttlefish 中，参数的声明、解析、验证，都通过 Fruit 容器 + FlagFeature 来注册和管理，实现更好的模块解耦和组合能力。
✅ 1. FlagFeature 实现：FastbootConfigFlagImpl

cpp
复制编辑
class FastbootConfigFlagImpl : public FastbootConfigFlag {
 public:
  INJECT(FastbootConfigFlagImpl(FastbootConfig& config, ConfigFlag& config_flag))
      : config_(config), config_flag_(config_flag) {}
这是一个标准的 依赖注入构造函数，它依赖两个对象：
	• FastbootConfig：写入配置
	• ConfigFlag：它本身是一个 flag 组件（这个是依赖项）
它实现了 FlagFeature 接口，允许参与 flag 的统一解析。
✅ 2. 定义并解析 flag

cpp
复制编辑
Flag proxy_fastboot_flag = GflagsCompatFlag(kName, proxy_fastboot);
ConsumeFlags({proxy_fastboot_flag}, args);
	• GflagsCompatFlag 会创建一个 flag 定义，如 --proxy_fastboot
	• ConsumeFlags 会扫描 args 中是否有这个参数
	• 如果找到如 --proxy_fastboot=true，就会自动设置：

cpp
复制编辑
proxy_fastboot = true;
然后：

cpp
复制编辑
config_.SetProxyFastboot(proxy_fastboot);
把这个值设置到了 FastbootConfig 结构中（通常是一个共享配置对象）。

✅ 3. 组件注册：FastbootConfigFlagComponent

cpp
复制编辑
fruit::Component<fruit::Required<FastbootConfig, ConfigFlag>, FastbootConfigFlag>
FastbootConfigFlagComponent() {
  return fruit::createComponent()
      .bind<FastbootConfigFlag, FastbootConfigFlagImpl>()
      .addMultibinding<FlagFeature, FastbootConfigFlag>();
}
注册了：
	• 一个绑定：FastbootConfigFlag 是 FastbootConfigFlagImpl
	• 一个多绑定：这是一个 FlagFeature，会参与 flag 处理流程

✅ 4. 调用流程：assemble_cvd
在 assemble_cvd 里这样写：

cpp
复制编辑
fruit::Injector<> injector(FlagsComponent);
auto flag_features = injector.getMultibindings<FlagFeature>();
FlagFeature::ProcessFlags(flag_features, args);
这时：
	• 会自动实例化 FastbootConfigFlagImpl
	• 构造函数里自动注入 FastbootConfig&
	• 执行 Process()，读取 args、设置 proxy_fastboot 的值

✅ 总结：这个机制的优势
优点	描述
✅ 解耦	每个 FlagFeature 可以独立定义在一个模块中，无需集中注册
✅ 可组合	通过 .install() 把多个组件组合进一个大的 flags 组件
✅ 可测试	单独测试每个 FlagFeature 不依赖全局 gflags 状态
✅ 生命周期托管	可以自动注入依赖、延迟构建




🔍 结论先行：--proxy_fastboot 的值由三部分决定（优先级从高到低）
	1. 命令行参数传入（最高优先）
	2. 默认值设置（程序内部设置，或通过 FetcherConfig 提取）
	3. 未设置时为空（由 .Process() 阶段报错或使用备用逻辑）

2.3.1 GetGuestConfigAndSetDefaults
从gflags 宏定义的参数（如 FLAGS_boot_image, FLAGS_kernel_path, FLAGS_system_image_dir 等）中提取出用于初始化多个虚拟机实例（guest）所需的配置。其实也就是收集了这三个flag

初次之外，还从相关的image中提取相关信息：
1）boot image 中提取 Android 版本（如 "13.0.0"），用于后续判断兼容性。
• ReadAndroidVersionFromBootImage(cur_boot_image)
2）提取system image 中的配置（android-info.txt）
auto res = GetAndroidInfoConfig(instance_android_info_txt, "gfxstream");
guest_config.gfxstream_supported = res.ok() && res.value() == "supported";


✅ 为什么这类 flag 还用 gflags 宏？
这些参数的特点是：
特性	是否符合
所有子模块都需要使用	✅ 是的
启动流程非常早	✅ 是的
不属于某个模块/子组件	✅ 是的
不需要注入/插件式扩展	✅ 是的

所以用 gflags 宏很合适。它们在程序最早期就被访问和使用，不适合通过依赖注入注入一个 flag processor。
✅ 和 FlagFeature/GflagsCompatFlag 有什么区别？
项目	DEFINE_* 宏	FlagFeature 机制
定义方式	DEFINE_bool/DEFINE_string 等	GflagsCompatFlag(...)
存储	全局变量（如 FLAGS_boot_image）	局部临时变量 + Setter 回调
模块感知	❌ 无	✅ 有
Fruit 注入	❌ 不支持	✅ 支持
XML 输出	❌ 基本无	✅ 支持 WriteGflagsCompatHelpXml
典型用途	启动早期配置、常用参数	模块化功能扩展、实验性功能
✅ 所以，Cuttlefish 中 Flag 的实际分类是这样的：
参数名	类型	机制	举例
--boot_image, --kernel_path	启动必须、全局	DEFINE_string + FLAGS_*	用于 ReadGuestConfig()
--proxy_fastboot, --display0	模块独立功能	FlagFeature + GflagsCompatFlag	用于各模块 Process()


总结：
ReadGuestConfig() 负责 从 gflags 参数与 boot/system 镜像中提取每个虚拟机实例的启动配置信息，是虚拟机启动配置流水线的第一环，直接决定后续 crosvm 启动方式与功能支持情况。


2.3.2 InitFilesystemAndCreateConfig
这是 launch_cvd 流程中的核心步骤之一，主要完成 配置初始化、文件系统准备、快照恢复、必要目录创建 等工作，最终将配置保存为磁盘可读的 JSON，并生成软链接，以便后续 assemble_cvd 和 run_cvd 使用。

Result<const CuttlefishConfig*> InitFilesystemAndCreateConfig(...) {
  {
    // config 初始化与恢复
    auto config = InitializeCuttlefishConfiguration(...);

    // 如果提供了 snapshot 路径，则进行 snapshot 恢复 + 打日志分隔
    if (!FLAGS_snapshot_path.empty()) {
        RestoreHostFiles(...);
        写入日志分隔线；
    }

    // 遍历每个 instance，判断是否需要重建 composite disk
    // 同时记录最大 sim 数量
    for (instance : config.Instances()) {
        OsCompositeDiskBuilder/ApCompositeDiskBuilder(...);
    }

    // 判断是否需要清理旧文件（根据 overlay 模式 + 是否重建）
    preserving = PreservingOnResume(...);
    CleanPriorFiles(preserving, ...);

    // 创建 root/config/instance/env 等目录
    EnsureDirectoryExists(...);

    // 为每个 instance 创建目录、vsock、GRPC、UDS 路径等
    for (instance : config.Instances()) {
        EnsureDirectoryExists(instance.xxxxx);
        CreateLegacySymlinks(...);
    }

    SaveConfig(config); // 重要：将内存中的 config 序列化到磁盘；保存之后 CuttlefishConfig::Get() 才能正确获取。
  }

  // config 保存之后重新获取 singleton（持久化版本）
  auto config = CuttlefishConfig::Get();

  // 替换 assembly_dir 软链接（为了兼容性）
  if (!InSandbox()) {
    symlink(config->assembly_dir(), FLAGS_assembly_dir);
  }

  // 替换 instance_dir_runtime 的软链接（为了 legacy 支持）
  if (!InSandbox()) {
    symlink(first_instance_dir, FLAGS_instance_dir + "_runtime");
  }

  // 创建动态磁盘文件（如 userdata、cache、metadata）
  CreateDynamicDiskFiles(...);

  return config;
}
